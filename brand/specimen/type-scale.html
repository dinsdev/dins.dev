Case study · 2026
A pipeline that tells you when it is wrong
I rebuilt a nightly data load so it checks its own output, and wrote down every decision along the way.

The old job ran for forty minutes and failed quietly about once a week. Nobody noticed until a dashboard looked strange. The new version validates each table against a contract before anything downstream reads it, so a bad load stops at the door instead of spreading.

Runtime 40 → 6 min · failures caught before publish 100% · example figures
How it works

Each source gets a small contract file: column names, types, allowed ranges. The loader runs check_contract() on every batch and writes the result to a log table that the alerting reads.

What I would change

The contracts live next to the code today. If more teams used them, they would belong in a shared registry with their own reviews. Read the contract format.
